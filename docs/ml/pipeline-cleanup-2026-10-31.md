# ML pipeline cleanup (2026-10-31)

The live machine was not mounted in this workspace. The notes below are from the code paths that produce the reported symptoms, plus the 2026-10-30 changelog entry that deleted Binance-trained `atlas-meta-crypto-*` registry directories. No model was retrained. No gate threshold was changed. Nothing here is a performance number.

Promotion gates stay `n_oos >= 200`, Brier skill `> 0`, log loss below the training base rate, deflated Sharpe `> 0.95`, PBO `< 0.5`, `shadow_weeks >= 4`. `execution_permission` stays `none`. A missing artifact is marked not eligible; it is never promoted.

## What changed

**Roll loop.** `scripts/ml_horizons_roll.py --loop` only appended `var/ml/horizons/roll.jsonl` when `retrain_cell` finished, so a long or stuck fit looked identical to a dead process. The loop now writes `cycle_start` before the child runs, heartbeats `roll_supervisor.json` while it waits, and the child heartbeats `roll_status.json` (phase such as `crypto-1m`). The child is killed after `--timeout` (default 4 hours; `0` waits with no cap). Timeout and traceback go to the same jsonl. A killed iteration does not promote. The pinball rule is unchanged: promote only when the challenger is no worse on at least 200 real bars neither model trained on.

**Duplicate interpreters.** On Windows a venv `Scripts\python.exe` is a redirector (`PC/venvlauncher.c`). It sets `__PYVENV_LAUNCHER__` and starts the base `Python312\python.exe`, then waits. `ml_horizons_roll.py` and `run_live_ingest.py` do not spawn a second interpreter. The pair is that redirector plus the interpreter whose pid is in `live_ingest.pid`. Current CPython puts the child in a job that ends when the redirector ends, so killing the launcher does not leave an orphan on a current install. The frontend did spawn the redirector (`frontend/server.mjs`). It now starts the base interpreter with `__PYVENV_LAUNCHER__` set, which is the same activation `multiprocessing` uses, and one process instead of two. The roll supervisor uses the same unwrap so the `--once` worker is not another redirector pair.

**Stale inputs.** `generate_live_prediction` defaulted the staleness floor to `max(3 * bar, 7 days)`. A 15m bar four days old was still `data_quality_status: VALID` while the market was open, including when the caller passed feed health `HEALTHY`. The default is now the coverage-service slack after the bar close, plus one bar (15m: 3 hours + 15 minutes; 1h: 6 hours + 1 hour; 1d: 4 days + 1 day, the existing weekend/holiday slack). An open market past that bound returns `STALE_MARKET_DATA` and does not score. A closed equity session still returns `MARKET_CLOSED`. Callers can still pass `stale_threshold_seconds`.

**Retired jsonl.** Nothing in the live sweep reads or writes `var/ml/live_predictions.jsonl`. The sweep ledger is `var/ml/predictions/*.sqlite`. The API no longer appends the jsonl. `GET /api/ml/prediction-health` reports `prediction_log.live_predictions_jsonl = retired`. The file on disk, if present, is historical and is not deleted by this change.

**Feature schema.** `atlas-pit-features-v2.4` is defined once, next to `dataset.FEATURES`. If a manifest stores a different feature list, live scoring returns `MODEL_UNAVAILABLE` and `data_quality_status: FEATURE_SCHEMA_MISMATCH` instead of `VALID`. Manifests that do not store a feature list are unchanged.

**Pooled horizon labels.** The 1m/5m trainer's 2-row embargo matches one series. Pooled frames interleave symbols, so a row's next-bar label can sit inside the calibration or test block. Fit and calibration now drop any row whose next same-instrument bar is not strictly before the next block. The hold-out slice and the pinball promote/keep rule are unchanged. This removes leakage; it does not claim a better pinball number.

**Registry versus refresh.** `code_sha()` ran git from `src/atlas/ai/ml` and then asked for the path `src/atlas/ai/ml`, which does not exist relative to that directory, so a dirty tree was recorded as clean. Git now runs at the repo root. A dirty tree gets a version id ending in `-dirty` and does not no-op onto the clean commit's directory. `GET /api/ml/refresh/last` marks a named version `artifact: missing` when the directory is gone, and downgrades `eligible` to `not_eligible` in that response only. It does not rewrite gates and does not promote. Refresh records `providers` / `provider_status` (`none` when no provider name is on the bars) and continues after a per-group error so one failure does not leave the previous report looking current. A null provider no longer crashes the model card (`none` instead of `join` on `None`).

## Research pass (short-horizon crypto and multi-asset)

Compared with López de Prado, *Advances in Financial Machine Learning* (2018), chapters 3 and 7; Bailey and López de Prado, *Journal of Portfolio Management* 40(5), 2014; Bailey, Borwein, López de Prado and Zhu on the probability of backtest overfitting (2017); Angelopoulos and Bates, *A Gentle Introduction to Conformal Prediction* (2021); Gibbs and Candès, NeurIPS 2021 (`arXiv:2106.00170`) and JMLR 2024 on adaptive conformal inference under shift; Arian, Norouzi and Seco, *Knowledge-Based Systems* 305:112477 (2024) on CPCV versus walk-forward; Grinsztajn, Oyallon and Varoquaux, NeurIPS 2022 (trees vs deep nets on tabular data); the Charles University thesis on BTC perpetual order-book forecasts (https://dspace.cuni.cz/handle/20.500.11956/213492); Haochuan Wang, “Exploring Microstructural Dynamics in Cryptocurrency Limit Order Books”, `arXiv:2506.05764` (2025); and Emre Inan, “Predictability of Funding Rates”, SSRN 5576424.

What ATLAS already does, and should keep:

- The meta-label is P(after-cost R > 0 | a primary setup’s side), not a model that invents the side. That is the AFML chapter 3 definition.
- Labels are a triple barrier: setup target, setup stop, and a vertical hold of one session (crypto: one UTC day). Training drops unfilled setups.
- The reported metric is purged walk-forward with the label finished before the test block minus a one-day embargo (`cv.py`). A k-fold that also trains on bars after the test block is the pitfall AFML §12.3 names. The 2024 KBS comparison prefers combinatorial purged CV when the goal is estimating backtest overfitting. ATLAS already runs CSCV for the PBO gate. Replacing the walk-forward number with CPCV would change the gate inputs. It was not done.
- Sample weights are average uniqueness on the training block only. Isotonic calibration is used at n ≥ 200, else Platt. Split conformal takes only the singleton {1}. Those calibrators are fit on a later block than the model, and the calibrator refuses an observation at or before `fitted_through`.
- Drift (PSI, ADWIN) is recorded and does not promote. Deflated Sharpe and PBO use the pre-declared trial set. Gates were not loosened.
- A deep sequence model was not added. On tabular features of this size, Grinsztajn et al. (2022) and the LOB study (`arXiv:2506.05764`) both find trees or logistic models match deeper nets once the inputs are fixed. ATLAS’s own `docs/ml/README.md` already says this.

What was wrong, and what this pass changed:

- Live scoring invented a detector from `ret_4` and `ema20_dist_atr`, zero-filled NaNs, invented a neutral probability, and subtracted fees again on top of after-cost R. None of that is in the training row. `generate_live_prediction` now calls `latest_open_setup`, which is the newest row from `build_rows(..., include_open=True)`. No open filled setup → `NO_SETUP`, probabilities null, `execution_permission` still `none`. The feature frame keeps NaN. Up/down is the binary meta probability on the setup’s side; neutral is 0 because the model has no third class. EV is `p*W - (1-p)*L` with W and L the fit-block mean after-cost R (`MetaModel.ev_r`). A setup detected at or before `calibrator.fitted_through` is `UNCALIBRATED` and is not passed to `decide`. The live window is still the last 300 closed bars.
- Expected effect: a `VALID` probability is now the same kind of number as an out-of-sample meta-label. It does not raise Brier, DSR, or lower PBO. Those gates were not re-run. Shadow weeks are still 0. The verification fixture’s oscillating session bars do fill an open setup, so those symbols stay `VALID`, now with `setup_source: setup_library`. A window shorter than the training builder’s 200 bars, or a window with no open fill, returns `NO_SETUP` and no probability.

## Not done, ranked by expected impact

1. **Retrain on Coinbase and Kraken after a real backfill, then shadow for four weeks.** This is the only step that can change eligibility. Expect `not_eligible` until `shadow_weeks >= 4` and the other gates pass. Do not restore the deleted Binance manifests. No new Sharpe or Brier is stated; this run did not train. Impact if the new book still fails Brier or PBO, as the last published card did: the model stays research-only, which is the correct outcome.

2. **Put adaptive conformal on the meta-label serve path, using the directional ACI already in `directional/aci.py`.** Gibbs and Candès (2021, 2024) show split conformal coverage fails when the series is not exchangeable, and an online α update restores long-run coverage. The directional book already measures ACI. Wiring it into `MetaModel.decide` changes take/skip without a fresh purged evaluation, so it was not switched on here. Impact: better abstention under drift, not a higher Sharpe by itself.

3. **Do not add order-book, funding, or open-interest features on the current bars.** The perpetual order-book thesis finds the imbalance signal gone as a tradable edge past about 30 seconds. Wang (`arXiv:2506.05764`) is the same regime (100 ms to a few seconds) and finds simpler models match deeper nets once the book features are fixed. Inan (SSRN 5576424) finds the next funding *level* is forecastable, not that funding forecasts the spot return. ATLAS crypto is spot OHLCV from Coinbase and Kraken; the perp venues were removed. Inventing those columns, or scraping a venue the product does not use, would break `atlas-pit-features-v2.4` and would not be the training distribution. Impact, if a permitted book or funding feed is added later and purged like the other features: a real candidate for the 1m book only. It is not a 15m/1h meta-label feature until that study exists.

4. **Configure a permitted equity and gold provider** if those groups should leave `provider_status: none`. An empty provider is not a model defect.

5. **Leave the horizon timeout at 4 hours unless a heartbeat shows a healthy fit running longer.** The Oct 30 quiet jsonl was the old “log only at the end” behavior. This workspace could not see whether that process was still inside LightGBM.

6. **Do not merge the directional pipeline into the meta-label pipeline, and do not replace walk-forward with CPCV inside the gates.** `atlas.ml` is an alias of `atlas.ai.ml`. CPCV is the better overfitting diagnostic in Arian et al. (2024); PBO already uses CSCV. Swapping the primary metric would rewrite every gate value. That is a design change, not a hygiene fix.

7. **`atlas-console up` still launches `sys.executable`.** On Windows that is the redirector, so core, watchdog, and console each show a pair. The same unwrap as the roll supervisor would remove those extra parents. It was left alone because it was outside the three processes originally reported, and the console launcher test starts real processes.
